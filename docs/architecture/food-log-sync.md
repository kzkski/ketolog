# 食事ログ（Web とモバイル）の同期方針

Ketolog の「今日」画面では、**Web** と **モバイル（Expo）** で食事ログのクライアント戦略が異なります。新規読者向けの対照表と要点だけをまとめます。読了目安 5 分程度です。

## 操作別の挙動（Web × モバイル）

| 操作 | Web | モバイル（Expo） |
|------|-----|------------------|
| **カートから記録（オンライン）** | 仮の `id` で一覧・PFC・カートを**先に更新**（楽観的 UI）。`saveMealToLog` が失敗したらカートとログ行・合計を**ロールバック**し、成功したら日付のログを**再取得**してサーバー行に置き換え。 | `food_log` への挿入が**成功するまで**、一覧を楽観的に増やさない。成功後 `load()` で**DB の内容を再読み込み**し、表示を揃える。 |
| **カートを記録（オフライン / 一時的な通信失敗）** | 本ドキュメント執筆時点では、Web はブラウザ前提の**オンライン主**挙動（未送信 outbox は持たない）。 | `enqueueFoodLogDraft` で**端末（AsyncStorage）の outbox**に積み、カートを空にする。通信が戻ったら**手動再送**（`sendFoodLogDraft`）で Supabase へ。重複挿入は `id` のべき等性で抑止。 |
| **食事行の削除** | 一覧と合計から**先に除去**（楽観）。`deleteFoodLogEntry` が失敗したら**前状態に復元**。 | ダイアログ承認後、Supabase の `delete` が**成功してから** `load()`。失敗時はトーストのみで UI は**先に消さない**。 |
| **記録直後の「真実のソース」** | 一瞬は仮行 → 再取得でサーバーの `id` 等に置換。 | オンライン成功時点で DB と一致。outbox 経由の行は、再送成功まで**未反映または下書き扱い**。 |

**Web 一言:** 応答性のため**楽観的 UI** を取り、失敗時にだけ元に戻す。

**モバイル一言:** 接続可能なら**サーバー書き込み成功 → `load` で信頼できる状態**、オフラインは**outbox に溜めて再試行**（楽観的に一覧へ足さない）。

実装の入口は、Web は `src/app/today/TodayClient.tsx` の `handleSave`（カート）と `useMealLog` の `handleDeleteEntry`、モバイルは `apps/mobile/screens/TodayScreen.tsx` の `saveCartToLog` と `apps/mobile/lib/food-log-outbox.ts` を参照してください。
