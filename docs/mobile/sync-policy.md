# モバイル（Native PoC）の同期・オフライン方針

GitHub Issue #270 のスコープに沿った **MVP 時点の正**。

## データの正

- **正本は Supabase（クラウド）** 上の `food_log` などのテーブルである。
- アプリ内の表示は **オンライン取得結果のキャッシュ** とみなす。
- オフラインや送信失敗時に端末へ残すのは **未送信の下書き（キュー）のみ** であり、クラウドと同等の「ローカルファースト」の複製ではない。

## オフライン時の挙動（食事の追加）

- ネットワークがオフラインと判定された場合、**即時の API 保存は行わない**。
- 入力内容は **AsyncStorage 上の下書きキュー** に保存する（ユーザーへ明示する）。
- **自動再送は行わない**。通信が戻ったあと、ユーザーが **「再送」** を押したときだけ `food_log` へ `INSERT` する。

## 再送時の重複防止（べき等性）

- 下書きごとに **クライアントが生成した UUID** を `food_log.id` として使う。
- 再送・タイムアウト後の再試行でも **同じ `id` で INSERT** するため、サーバー側で既に行が存在する場合は一意制約違反（`23505`）となり、**成功とみなして下書きを削除**する（二重登録しない）。

## 競合（MVP の暫定ルール）

- **Web とモバイルの同時編集**など高度なマージは対象外。
- 同一行に対する更新は **最後に成功した書き込みが有効**（サーバー上の通常の更新セマンティクス）。未送信下書きは別行の追加として扱う。

## 非スコープ（本 Issue ではやらない）

- 完全なローカルファースト同期基盤
- 高度な競合解決アルゴリズム
- バックグラウンドの自動再送キュー
