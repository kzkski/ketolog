## 1. 分析画面（/insights）上部コントロール：第1案＝横詰め・1行化を優先

**方針**: 折りたたみは主手段にしない。まず **同種コントロールを横に並べ、モバイルでも行数を減らす**。

### レイアウト意図（ワイヤーフレーム）

画像: [`docs/plans/wireframe-insights-mobile-controls.png`](wireframe-insights-mobile-controls.png)（Cursor 生成の低忠実度ワイヤー。構成の合意用）

```text
┌─────────────────────────────────────────┐
│ 分析                          [閉じる]   │
├─────────────────────────────────────────┤
│ [過去7日] [過去30日]  カスタム最大90日※  [DL]   │  ← 1行目（※は補助テキスト、ボタンではない）
│ [開始日____] [終了日____] [適用]         │  ← 2行目（開始・終了は同一行の左右）
├─────────────────────────────────────────┤
│ 平均PFC …                               │
└─────────────────────────────────────────┘
```

- **「カスタム最大90日」**: クリック不可の説明。プリセット行の横に **小さなキャプション**として置く（ボタン列と誤解されないサイズ・色）。カスタム適用後だけ表示するのではなく、常に見える形でもよい（ユーザーは「わかった方がいい」とのこと）。
- **過去7日 / 過去30日 / ダウンロード**: 同一行に **操作可能なコントロールのみ** を並べる。DL はアイコン＋短いラベルで幅節約可。
- **開始日・終了日**: 現状の縦 `grid` をやめ、**1行2カラム＋適用ボタン**（`flex` / `grid-cols-[1fr_1fr_auto]` 等）。はみ出し対策に `min-w-0`、必要なら `text-sm` と input の `max-width`。
- **タブレット以上**: 既存の広いレイアウトを維持しつつ、同じ情報設計に揃える。

### セーフエリア

- ノッチ・ホームインジケータ対策は [`InsightsClient.tsx`](../../src/app/insights/InsightsClient.tsx) に **上下 `env(safe-area-inset-*)` を付与**（[`TodayClient`](../../src/app/today/TodayClient.tsx) とトーンを揃える）。詳細は実装時に調整。

## 2. 更新通知：実行中バージョン vs CHANGELOG 上の最新版 ＋ 概要一文

**ゴール**: `NEXT_PUBLIC_APP_VERSION`（実行中）と、リモートの `CHANGELOG.md` から解釈した **最新リリース版**を比較し、古ければ通知。本文は **Keep a Changelog 形式**（リポジトリの [`CHANGELOG.md`](../../CHANGELOG.md)）から、該当バージョン節の **先頭付近の箇条書きを短く要約**して表示。

### データ取得

- **Raw Markdown**: GitHub の blob URL は HTML になるため、クライアントでパースするなら **raw URL が必要**。
  - 例: `https://raw.githubusercontent.com/<owner>/<repo>/main/CHANGELOG.md`
  - 既存の `NEXT_PUBLIC_CHANGELOG_URL`（blob）から raw を **導出するヘルパ**を用意するか、任意で `NEXT_PUBLIC_CHANGELOG_RAW_URL` を追加するかは実装時に決定（導出の方が env 増やさずに済む場合あり）。

### パース（クライアント）

- `## [Unreleased]` はスキップ。
- `## [X.Y.Z] - YYYY-MM-DD` 形式のうち、**セマンティックバージョンで最大**のものを「リリース上の最新」とする。
- その節の `### Added` / `Fixed` / … の **最初の `- ` 行を1つ採用**（または先頭2件を結合して最大文字数で切る）→ 通知用の短い概要。

### Service Worker との役割分担

- **バージョン比較**: CHANGELOG 由来（上記）。「サーバに新しい版がある」ことをユーザーに伝える。
- **実際に新しいバンドルを取る**: 既存 [`public/sw.js`](../../public/sw.js) の更新に加え、`registration.update()` → 待機中ワーカーがいれば **`skipWaiting` + `controllerchange` で `location.reload()`**（またはユーザー操作直後）。

### 表示位置：ヘッダー中央のメッセージ帯

- [`TodayClient.tsx`](../../src/app/today/TodayClient.tsx) では中央が `headerHint`（今日の日付・栄養ヒント用）専用。
- **改訂方針**: 「アプリ更新あり」を **栄養ヒントより優先**して同じ帯に出す（クリックでリロード／更新完了）。栄養ヒントは更新がないときのみ、または更新通知が消えた後に従来どおり表示。
- 実装詳細: `headerHintRaw` と並立する `updateBanner` 的な state、または `headerHintRaw` の計算前に「更新あり」をマージする単一の表示用 `useMemo`。
