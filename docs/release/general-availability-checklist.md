# 一般公開（GA）チェックリスト

**ゴール**: 不特定多数が自力で登録でき、**濫用・法務・コスト・インシデント**に耐える。

前提の整理は [beta-checklist.md](beta-checklist.md)。コスト・枠は [operations-and-costs.md](operations-and-costs.md)。テストは [quality-and-ci.md](quality-and-ci.md)。

## 1. アカウントライフサイクル（実装）

| 項目 | 内容 |
|------|------|
| **アカウント削除** | UI（設定）から申請 → **サービスロール**で `auth.admin.deleteUser` 等を実行する Server Action / Route Handler、または Supabase 推奨パターン。DB は `ON DELETE CASCADE` でユーザー行が消える前提を文書化。 |
| **パスワードリセット・メール変更** | Supabase 標準フローを UI に接続済みか確認し、不足なら追加。 |

## 2. 濫用・セキュリティ（実装＋設定）

- **サインアップ濫用対策**: Supabase の **CAPTCHA**、**レート制限**、必要なら招待制の維持。
- **`shared_products`**: 書き込みポリシーの見直し（サーバー経由のみ、不正バーコードの抑制、監査ログ）。関連: [Issue #2](https://github.com/kzkski/ketolog/issues/2)。
- **RLS・権限の再監査**: `GRANT ... TO anon` 等が本番で必要な範囲か確認。
- **シークレット管理**: 本番キーのローテーション、Vercel / ローカルの権限。

## 3. 法務・コンプライアンス（実装＋文書）

- **本番向け利用規約・プライバシーポリシー**（メール、食事ログの性質、第三者 API、保存期間、問い合わせ窓口）。
- **Cookie / 外部送信**（分析・広告を入れたら表記。未使用なら「使っていない」旨の整理でも可）。
- **未成年・医療免責**（健康アプリとしての注意書きを検討）。

## 4. プロダクト・コミュニケーション

- [README.md](../../README.md) の「一般向け非公開」撤廃、**ランディング**や PWA 説明の整備。
- **FAQ**（データの持ち出し、オフライン、サポート範囲）。
- **成長・エコシステム指標（参考）**: 登録数・MAU・継続率に加え、将来、分析・外部連携・B2B など**下流の価値**を製品に含める場合は、ログ単体とは別の KPI（例: 連携機能の利用率、エクスポートの用途別内訳）を定義することを検討する。背景の整理は [docs/research/README.md](../research/README.md)。

## 判断が分かれそうな点

一般公開後も **招待制を残すか**、**無料枠の制限**（例: 保存日数）を設けるかはプロダクト方針次第。ここでは **技術的に必要な下限**にフォーカスしている。
