# v3 ネイティブアプリ化検討メモ（非ブロッキング）

このドキュメントは、v3 一般公開に向けて **ネイティブアプリ化を判断するための材料整理**を目的とする。  
現時点では実装計画ではなく、判断軸の頭出しを扱う。

## 位置づけ

- v2 のベータ公開ゲートをブロックしない（非ブロッキング）。
- v3 での Go/No-Go 判断を迷わないため、論点と前提を先に揃える。
- 実装着手時は Issue を作成し、本書は判断の正本として更新する。

## 目的

- PWA 継続 / ネイティブ化 / ハイブリッドの選択肢を比較可能にする。
- 一般公開時点のユーザー体験と運用体制に対し、どの方式が妥当かを判断できる状態にする。

## 検討観点

### 1. プロダクト観点

- ネイティブ化で改善したい体験は何か（例: 通知、カメラ利用、継続率）。
- 現行 PWA で代替可能な範囲と、代替しにくい範囲の切り分け。
- v3 ローンチで必須にする機能と、後続リリースでよい機能の分離。

### 2. 技術観点

- Next.js / Supabase / 認証基盤の再利用方針。
- 候補方式（React Native / Expo / Flutter / 完全ネイティブ）の比較軸。
- セッション管理、オフライン同期、更新配布、監視基盤の設計方針。

### 3. 運用観点

- App Store / Google Play 審査対応の要件確認。
- リリース運用（署名、証明書、ロールバック、クラッシュ解析）の整備項目。
- サポート導線・問い合わせ・障害時の一次対応フロー。

### 4. 法務・コンプライアンス観点

- モバイル配布時の利用規約・プライバシーポリシー更新範囲。
- ストア要件（アカウント削除導線など）の反映有無。
- 外部 API 利用条件（OFF 等）の継続遵守方針。

### 5. コスト・体制観点

- 開発/保守工数、QA端末、CI/CD の追加コスト。
- 継続運用に必要な担当体制（開発・運用・サポート）。
- 収益化前提が未確定な段階で許容する固定費の上限。

## 判断アウトプット（最小）

- 方針: `PWA継続` / `ネイティブ化` / `ハイブリッド`
- 採用理由: 3-5 行
- v3 スコープ: 必須機能と除外機能
- 実装開始条件（Go 条件）: 2-4 項目
